# Write a testable spec

Define what a feature should do before the team builds it. Use the same approach for an initial brief or a change to existing behaviour.

## Example prompt

> Our brief says a colleague can sign up for a session with ten places. Write a short spec. What does the tenth participant see after signing up, and what does the next person see? We haven’t discussed a waiting list yet. Record that as an open question.

## What do you get?

A scoped spec with the objective, intended behaviour, observable acceptance criteria and open questions. For an existing feature, a focused update describes the change from current to intended behaviour.

The team can use the acceptance example to start building and testing. To review whether users understand an interaction, try it together in your own prototype. The optional [prototype-shell](prototype-shell.md) skill lets you discuss the screen and its spec side by side.
